# ButtonsCLI docs site

[Astro](https://astro.build) + [Starlight](https://starlight.astro.build). The
pages come from [`docs/guide/`](../docs/guide/index.md); this folder only holds
the site's code and looks. Write docs in `docs/guide/`, never in
`src/content/docs/` (generated, ignored by Git).

```sh
cd site
npm install
npm run dev      # http://localhost:4321/buttonscli-native/ , reloads on docs/ edits
npm run build    # static site in dist/
```

Node is only needed for the site; the app itself stays Node-free.

## How Markdown becomes the site

[`integrations/sync-docs.mjs`](integrations/sync-docs.mjs) runs on every
`dev`/`build` (and `npm run sync`). It copies `docs/guide/*.md` into
`src/content/docs/` and:

- turns `page.md` links into site links, and links elsewhere in the repo into
  GitHub links;
- turns `<!-- IMAGE: … -->` comments into **Screenshot wanted** boxes, or the
  image once `docs/guide/images/<file>` exists (see
  [`docs/guide/IMAGES.md`](../docs/guide/IMAGES.md));
- adds the hero to the home page and an **Edit page** link to the source file;
- lists every screenshot spot in `src/generated/shots.json` for
  `/screenshots/` (not in the sidebar).

A new `docs/guide/*.md` page appears under **More** in the sidebar; give it a
group in `GROUPS` in [`guide.config.mjs`](guide.config.mjs).

Environment options: `DOCS_HIDE_PLACEHOLDERS=1` (no placeholder boxes),
`DOCS_ALL_LOCALES=1` (every app language, untranslated pages fall back to
English), `DOCS_DEFAULT_LOOK`, `DOCS_DEFAULT_MODE` (`dark`, `light`, `auto`),
`DOCS_SITE` and `DOCS_BASE` (host; default GitHub Pages at
`/buttonscli-native`).

## Looks, mode and accent

The palette button in the header opens **Appearance**: Dark / Light / Auto
(follows the OS), a **Look** and an **Accent**. Choices are kept in the
browser's local storage. The default is dark + Classic.

| Look | Fonts | Feel |
| --- | --- | --- |
| Classic | Inter, JetBrains Mono | Clean docs, navy dark mode |
| Neon | Outfit headings, Inter | Glowing panes; each section has its own color (green start, cyan workspace, violet themes, magenta shaders, amber AI, coral reference) |
| Paper | Source Serif 4, Inter for navigation | Editorial, warm |
| Terminal | IBM Plex Mono | Phosphor green, `##` headings |

- Colors and fonts: [`src/styles/looks.css`](src/styles/looks.css), one block
  per look, each with dark and light grays.
- The switcher: [`src/components/ThemeSelect.astro`](src/components/ThemeSelect.astro)
  (replaces Starlight's theme select) and
  [`src/components/ThemeProvider.astro`](src/components/ThemeProvider.astro)
  (applies the choice before first paint, so nothing flashes).
- To add a look: add it to `LOOKS` in `guide.config.mjs`, copy a block in
  `looks.css`, and add its preview colors in `ThemeSelect.astro`. Fonts come
  from `@fontsource` packages listed in `astro.config.mjs`.

## Languages

Translations live in `docs/guide/i18n/<lang>/<page>.md`, using the app's
locale codes (`es`, `de`, `ja`, `pt-BR`, `zh-CN`…; all 20 are in
`LANGUAGES`). A language appears on the site, with a language picker, once its
folder exists; pages it doesn't have yet show the English page with a notice.
Restart `npm run dev` after adding a language.

Write translated pages as if they sat next to the English one: same links
(`shaders.md`) and image paths (`images/x.png`).

Front matter that the site reads:

- `machineTranslated: true` shows an "AI translated, corrections welcome" banner.
- `sourceHash: <hash>` records which English version was translated. When the
  English page changes, the page shows "the English page has changed".

### AI translation

```sh
export TRANSLATE_API_KEY=...            # any OpenAI-compatible endpoint
export TRANSLATE_MODEL=<model name>     # a model on TRANSLATE_BASE_URL
npm run translate -- --lang es,de,ja --page index,getting-started
npm run translate -- --lang all --stale  # refresh only missing or outdated pages
npm run translate -- --lang ja --page shaders --dry-run   # show the glossary
```

[`scripts/translate.mjs`](scripts/translate.mjs) gives the model a glossary
built from the app's own catalog (`src/i18n/*.json`), so **bold** UI labels
match what the translated app shows; labels the app hasn't translated stay
English. It never overwrites a hand-written page (no `sourceHash`) unless you
pass `--force`.

Site strings (Appearance, banners, sidebar groups) are in `UI` in
`guide.config.mjs`; Starlight translates its own interface.

## For AI readers

`/llms.txt`, `/llms-full.txt` and `/llms-small.txt` are generated by
`starlight-llms-txt`, with the "Notes for AI assistants" from
`docs/guide/llms.txt`.

## Deploying

`npm run build` writes a static site to `dist/`. For GitHub Pages, enable
Pages with "GitHub Actions" as the source and build `site/` with
`withastro/action`, or upload `dist/`. For another host or a custom domain,
set `DOCS_SITE` and `DOCS_BASE` (for example `DOCS_BASE=/`).
